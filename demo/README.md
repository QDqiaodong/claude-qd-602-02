# 完工验收与返修闭环 · 演示说明

调律师处理完服务单不能直接结单，必须**提交完工记录**（本轮处理内容 / 检测结果 / 交付说明），
服务单进入**待验收**；店员在维修页看到验收待办，选择**验收通过**或**退回返修**。
退回必须填写仍存在的故障与返修要求；原完工记录与历次验收结论全部按轮次保留，返修后可再次提交，
直到最新一轮验收通过，服务单才算真正完成。

## 一、状态机

```
已排期 PLANNED ──开始施工──▶ 进行中 DOING ──提交完工──▶ 待验收 PENDING_ACCEPT
     │                            ▲                          │
     └──取消──▶ 已取消 CANCELED     │              ┌───────────┴───────────┐
                                   │              │                       │
                            返修中 REWORKING ◀─退回返修─              验收通过
                                   │              │                       │
                                   └──再次提交完工─┘                       ▼
                                                                   已完成 DONE（终态）
```

- 通用 `/status` 接口只保留「开始施工 / 取消派单」；完工、验收、退回、再次提交全部是**专属接口**，
  不能靠改状态文字跳步。
- 终态 `DONE / CANCELED` 不能通过刷新、重复提交、调换请求顺序重新进入返修。

## 二、乐器状态联动（服务单 ↔ 乐器）

| 动作 | 维修 REPAIR / 大修 OVERHAUL | 调律 TUNING |
| --- | --- | --- |
| 开始施工 | 记录原状态快照，在库乐器置为「维修中」 | **不动**乐器状态 |
| 提交完工 / 待验收 / 返修中 | 继续保持「维修中」 | 不动 |
| 退回返修 | 继续「维修中」 | 不动 |
| **最新一轮验收通过** | 按开工前快照恢复（默认回在库）；同乐器还有其它在途维修单时保持维修中 | 不动 |
| 处理期间乐器被报废 | 验收通过照常留服务记录，**乐器保持报废、不复活** | 不动 |

## 三、并发与回滚

- 提交完工 / 验收都在**一个数据库事务**内：先对服务单行 `SELECT ... FOR UPDATE` 加行锁串行化，
  再用**条件更新** `UPDATE ... WHERE status = 期望状态` 落库；
  轮次表带唯一键 `uk_order_round_phase(service_order_id, round_no, phase)` 兜底。
- 连点提交、网络重试：只有第一次生效，后来者收到「第 N 轮完工已存在 / 当前为待验收」提示。
- 两名店员同时作出相反结论：只有一个生效，被拒方收到带当前轮次、最新状态的中文提示。
- 任何一步写入失败：轮次记录、服务单状态、乐器状态随事务整体回滚，不留半完成链路。
- 列表、详情、乐器行内展开历史共用同一套轮次装配，刷新后结论一致。

## 五、手动演示路径（浏览器）

1. 打开「调律与维修」页，顶部可见**店员验收待办**卡片（#6）。
2. 展开 **#1（进行中）**：点「提交完工」→ 填处理内容 / 检测结果 / 交付说明 → 状态变「待验收」，
   顶部待办出现该单，乐器保持维修中。
3. 在待办里点「退回返修」→ 必填仍存故障、返修要求、店员姓名 → 状态变「返修中」，
   展开可见第 1 轮的完工记录与退回结论并列保留。
4. 点「再次提交完工（第 2 轮）」→ 重新进入待验收；展开可见第 1、2 轮按时间完整还原。
5. 点「验收通过」→ 服务单「已完成」，乐器恢复「在库」；再点任何操作都被明确拒绝。
6. 打开「乐器台账」展开对应乐器，维修历史里同一服务单可展开看到完全相同的轮次结论。

## 六、自动化端到端验证

```bash
# 需要后端运行在 8362（docker 启动时即为此端口）
python3 demo/e2e_acceptance.py
# 或自定义地址
BASE=http://127.0.0.1:8362 python3 demo/e2e_acceptance.py
```

覆盖 53 项断言：旧数据兼容、完整闭环、调律不动乐器、报废不复活、终态边界、
两店员并发相反结论、连点提交唯一一轮、缺字段整体回滚等。可对干净种子数据重复执行。

## 七、接口一览

| 接口 | 说明 |
| --- | --- |
| `POST /api/service-orders/{id}/completions` | 调律师提交完工（三件套必填），进行中/返修中 → 待验收 |
| `POST /api/service-orders/{id}/acceptance` | 店员验收：`ACCEPTED` 通过 / `REJECTED` 退回（故障+要求必填） |
| `POST /api/service-orders/{id}/status` | 仅开始施工 `DOING`、取消 `CANCELED` |
| `GET  /api/service-orders` | 列表，带 `currentRound`、`latestDecisionName`、`rounds[]` 轮次记录 |
| `GET  /api/instruments/{id}/history` | 乐器展开历史，服务单内嵌同一套轮次记录 |
